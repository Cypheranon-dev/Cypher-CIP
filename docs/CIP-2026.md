# Cypher CIP-2026: Privacy, Quantum Safety, Offline Settlement

**Research update — October 2026**  
Aligned with current market demand for institutional privacy, post-quantum resilience, and offline operation.

## 1. Privacy by Default + Zero-Knowledge Compliance

**Market signal**  
- Midnight, Aztec, and recent Starknet work (eprint 2026/474) show demand for confidential transfers that still allow selective disclosure to authorized auditors.  
- Selective Disclosure Authorization Schemes (SDAS) and threshold view-keys (FATF Travel Rule / MiCA) are the emerging pattern: privacy is the default; compliance is a revocable, scoped capability.  
- Cardano’s native confidential transfer CIP and Solana Confidential Balances demonstrate that amount privacy without full anonymity is already shipping.

**Cypher design**  
- Shielded by default (CIP STARK circuit hides sender, receiver, amount).  
- Optional compliance view-key: user registers an encrypted viewing key; a threshold of designated auditors can decrypt only under legal trigger.  
- Viewing keys are Dilithium-signed and revocable. Uninvolved users remain private.  
- No trusted setup. Compliance proof is a separate, optional STARK that does not weaken the base privacy circuit.

## 2. Quantum-Safe + Hack Recovery via Consensus

**Market signal**  
- NIST ML-DSA (Dilithium) and Falcon are the leading candidates; Hardy Index ranks Quantus, Dilithion, and QRL highest for native PQ.  
- Signature size is the bottleneck (ML-DSA-87 ~3.3 KB). Hybrid or witness-segregated approaches are under active research.  
- Recent papers explore threshold Dilithium, dynamic key rotation, and verifiable timed signatures to raise the cost of key-compromise attacks.  
- Rollback of finalized transactions is rare; the practical pattern is a short challenge window plus validator consensus for emergency freezes or reversals under clear governance rules.

**Cypher design**  
- All spends require Dilithium5 (ML-DSA-87) signatures inside the STARK circuit.  
- Optional emergency recovery: within a protocol-defined challenge window, a supermajority of validators can co-sign a recovery transaction that reverts a proven-hack spend. The recovery itself is a STARK-proven, Dilithium-signed action recorded on-chain.  
- After the window, finality is absolute. No silent rollback.  
- Viewing keys and recovery keys are rotated via the same PQ signature scheme.

## 3. Offline / Air-Gapped / Mesh Transactions

**Market signal**  
- Offline Protocol (350k+ devices), BTC Mesh (Meshtastic/LoRa), Apple Find My experiments, and air-gapped QR protocols (IEEE ICBC 2026) show real demand for internet-free settlement.  
- Common pattern: sign offline, relay via BLE/WiFi Direct/LoRa/mesh, settle when any hop reaches a connected node.  
- Airdrop-style bearer tokens and store-and-forward meshes are shipping today.

**Cypher design**  
- Transactions are self-contained STARK proofs + Dilithium signatures.  
- A signed transaction can be moved by:  
  - QR / AirDrop / Bluetooth / WiFi Direct / LoRa mesh (store-and-forward).  
  - Any node that later gains internet connectivity can broadcast it.  
- No online dependency for signing or initial relay.  
- Mask Wallet already supports offline QR signing; CIP extends this to mesh relay of the proof payload.

## Summary

| Requirement | Mechanism | Status |
|-------------|-----------|--------|
| Privacy + ZK compliance | Default STARK privacy + optional threshold view-key | Design |
| Quantum-safe + recovery | Dilithium5 + challenge-window validator recovery | Design |
| Offline / mesh | Self-contained proofs relayed over BLE/mesh/QR | Design |

These three properties together do not exist in any deployed L1 as of October 2026. Cypher’s CIP is the research vehicle for combining them without a trusted setup.
